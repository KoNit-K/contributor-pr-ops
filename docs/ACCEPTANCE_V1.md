# Contributor PR Ops — V1 交付与验收标准

文档版本：1.2 · 配套：[DESIGN_V1.md](DESIGN_V1.md)。

这是执行时采用的验收要求，不是测试结果；初始全部为 `NOT_RUN`。环境具体版本由开发者在实现时选定并验证，不沿用旧稿预设版本，也不新增环境管理平台。

## 1. 什么算完成

完整一期必须同时通过：

1. **工程验收**：独立应用、真实实现、固定场景测试、通用配置和干净安装可复现。
2. **真实验收**：实际目标只读采集、可核对贡献基线、样本逐项复核及两次同步完成。
3. **发布验收**：公开仓库、代码历史、持续集成（Continuous Integration，CI）、标签、发布（Release）和归档可核对。

开发完成、离线通过、在线受阻、发布完成分别报告。必验项 `FAIL`、`BLOCKED` 或 `NOT_RUN` 时，不声称一期全部完成，不发布声称一期完整的 `v0.1.0`。

程序因实际数据/语义不足产生 `UNKNOWN` 或 `INSUFFICIENT_EVIDENCE` 可以是正确结果；未实现功能、没有尝试必要采集而统一返回未知，不算完成。可以分阶段提交公开开发代码，不必等全部完成才首次推送。

## 2. 必交付物

| 交付物 | 通过标准 |
|---|---|
| 源码仓库 | 独立、公开、有阶段提交、实际实现和测试，不是只有目录/提示词/占位接口 |
| 本地程序 | 维护与贡献统计两条业务线，关闭所有智能体仍可运行 |
| sample 与环境 | 实现时选定的稳定参考环境、真实依赖锁、通用样例、标准安装说明 |
| 本地个人配置 | 真实账号、目标、邮箱映射、数据与报告不进入公开内容 |
| 验证入口 | 同一套可复现工程测试、固定业务验收和干净安装流程 |
| 使用文档 | 安装、配置、命令、统计口径、限制、贡献和安全/发布说明 |
| 发布版本 | 同一已验证提交的标签、Release、通用源码归档和校验值 |
| 执行报告 | 环境、命令、实际结果、提交/CI/发布链接、在线覆盖度、具体限制 |

## 3. 一期必验矩阵

### A01 — 干净安装与通用配置

**怎么验：**在干净目录安装同一提交，使用两套合成配置分别切换仓库、作者、主分支、时区和认证身份；测试配置缺失/非法及重复初始化。

**通过条件：**
- 按 README 即可安装，不修改源码或开发者本机绝对路径。
- 认证账号可与被统计作者不同；缓存和结果按正确目标隔离，不能串用数据。
- sample 不包含真实部署值；`init` 不覆盖已有配置、不联网。
- 无 GitHub 凭据也可运行帮助和离线测试。

**证据：**干净安装命令及结果、两套配置输出、初始化与非法配置测试。

### A02 — 被扫描仓库严格只读

**怎么验：**模拟传输层记录全部业务请求；临时 Git 仓库记录前后状态；执行同步、调查、本地处置和统计。

**通过条件：**
- 被扫描 GitHub 仓库写入为零；不评论、关闭、合并或解决线程。
- 图查询语言（GraphQL）读取使用 POST 允许，但 mutation 不暴露。
- 不变基、推送、强推或覆盖用户贡献分支，不执行目标仓库代码/测试/钩子。
- fetch/克隆按设计使用独立受控目录；外部工作树不被改动。
- 本地 acknowledge 只写本地；本项目开发和发布权限不扩展到目标仓库。

**证据：**请求断言、Git 状态对照、外部工作树保护用例。

### A03 — 简单节流

**怎么验：**使用虚拟时钟、模拟额度桶和响应，不做真实账号压力测试。

**通过条件：**
- 默认比例 0.40，0.30/0.50 配置生效；官方额度模拟为 100 时，40% 允许用到 40，下一计费请求等待或暂停。
- 所有运行时应用程序接口（Application Programming Interface，API）请求与重试走同一入口；同时在途请求最多一个，默认间隔和低额度桶放慢生效。
- 按实际桶上限、剩余量和窗口控制，不固定假定所有凭据额度相同；GraphQL 按点数预留并根据响应校正，不按一次请求等于一点。
- 遵守 `Retry-After`/reset；最多两次重试，不在多层各自重试；持续限流结束本轮而非继续下一个 PR。
- 普通权限错误不会成为无限重试。重启保留当前窗口用量/等待时间；第二个 sync 被简单本地锁阻止。
- 没有恢复成每日预算平台、逐请求审计数据库、分布式限流或复杂熔断系统。

**证据：**模拟请求时序/计数断言、重启与锁测试。未知 GraphQL 成本超预估时如实校正并停止继续超用，不伪称执行前能绝对预知成本。

### A04 — 作者清单、分页和完整性

**怎么验：**准备 0、1、100、101、1205 个目标拉取请求（Pull Request，PR）的固定数据；加入其他作者/仓库干扰项，包含草稿、历史合并、关闭未合并及多页评论/线程；模拟重复页、最后一页失败和部分 GraphQL 结果。

**通过条件：**
- 静止的 1205 条完整测试集合，恰好产生 1205 个唯一目标项；不能停在前 1000 条或混入干扰项。
- 草稿计入 Open；手动排除只影响维护队列，不影响贡献总数。
- 顶层与嵌套分页均可核查完成；失败不将未返回项目当成关闭，不推进完整成功标记。
- 真实扫描中数量变化要有时间和差异说明，不假称原子一致快照。

**证据：**独立固定期望清单、实际清单、分页与缺口记录。

### A05 — 增量、去重与恢复

**怎么验：**相同输入同步两次；分别新增/编辑评论、审阅、线程、head、主分支和既有关联对象；中断后续跑且重复一次续跑。

**通过条件：**
- 不重复创建待办、反馈、关系、采用记录或每日新增。
- 完整有效的旧证据可复用，不每次重读全部历史；编辑旧评论不能仅因 createdAt 不变而漏掉。
- 关联来源/主分支独立变化不会永久被 PR updatedAt 缓存隐藏。
- 失败不覆盖有效快照；恢复后与等价完整执行结果一致。
- 首次未读全的项目不能成为 NO_ACTION；报告区分已核查、缓存结果、待检查。

**证据：**前后数据库与输出对照、请求类别计数、恢复测试；不凭空承诺固定节省比例。

### A06 — 作者维护规则

实现九类主状态与并列线索：
`NO_ACTION`、`CONFLICT`、`MAINTAINER_ACTION`、`THIRD_PARTY_FEEDBACK`、`WAIT_REVIEWER`、`MAINTAINER_EDITED`、`UPSTREAM_CHANGED`、`CLOSE_CANDIDATE`、`INSUFFICIENT_EVIDENCE`。

| 固定场景 | 应有结果 |
|---|---|
| 当前事项已完成、证据足够、无冲突或外部事项 | NO_ACTION；年龄/behind-main 不制造待办 |
| 作者最后说“稍后改” | 具体待办仍存在，不能自动转等待复审 |
| 三项意见只处理两项 | 只处理对应两项，第三项仍可见 |
| 新提交与特定意见无关 | 不因提交时间较新就清除意见 |
| 第三方新反馈 | 第三方队列或明确待核查，不冒充维护者要求 |
| 核实的当前维护者要求 | 维护者队列，原文/证据与待办可追溯 |
| 对应修复/本地确认已完成 | WAIT_REVIEWER，不自动 resolve GitHub 线程 |
| 有维护者直接修改证据且无新要求 | 记录并等待，不建议覆盖其修改 |
| 维护者修改后又有要求或冲突 | 并列保留，不被修改事件遮蔽 |
| 纯批准、感谢、非阻塞小意见、维护者之间讨论 | 区分无需修改、普通建议和待核查，不全部当阻塞 |
| 未知可合并性、身份或未读完整内容 | 明确缺口，不当无冲突/无需处理 |
| 当前真实测试失败与无部署/非必需/旧检查等 | 保留正确检查事实及范围，不以无部署代替失败或通过，不误关 PR |

**通过条件：**固定预期全部通过，角色有依据，每条结果可定位源反馈。自然语言可通过本地人工确认进入规则，测试要区分“未经确认”与“已有核验”。不能调用模型、几个关键词或统一 UNKNOWN 代替实现。

**证据：**场景测试、决策优先顺序、逐项反馈和本地确认记录。

### A07 — 上游关系与关闭候选

**怎么验：**新引用、旧关联 PR 后来合并、原 Issue 关闭；同文件/标题/标签；“准备 cherry-pick”而未执行；提到的是别人的 PR；完整覆盖、部分采用和回退；旧确认后出现新 head。

**通过条件：**
- 关联来源、动作账号、时间和证据链接正确；旧来源更新仍被发现。
- 无关联 Issue 不判无效；Issue 单独关闭、同文件、标题、标签和未来计划不产生关闭结论。
- 语义不明时说明待核查什么，不按关键词确认。明确决定或完整覆盖必须有有效依据，允许带版本的本地人工核验。
- 部分采用、等价匹配失败、历史采用后回退不能自动判整个 PR 可关闭。
- 关键证据/head 改变使受影响旧确认失效；建议关闭不执行任何关闭操作。

**证据：**关系场景、候选来源、确认有效性与弱证据反例测试。

### A08 — 贡献统计和采用归因

**怎么验：**在临时 Git 仓库构造普通合并、压缩合并（squash merge）、变基合并（rebase merge）、原对象进入、等价补丁、明确拣选提交（cherry-pick）来源、部分采用、共同署名、重名、回退和浅历史。GitHub PR 状态配套合成数据。

**通过条件：**
- PR 生命周期、采用程度、证据类型分开；重叠证据不重复相加。
- 正式合并只计配置主分支，包含普通/压缩/变基方式。
- 一个正式合并 PR 含本人三个提交、他人一个合并提交：本人主要作者提交为 3、正式 PR 为 1。
- 三个源提交压成一个本人署名上游提交：主要作者上游提交为 1、正式 PR 为 1，不继续算 3。
- 同一上游提交多次匹配只计一次；主要作者与共同署名分列，提供去重并集。
- 身份依赖已核实邮箱/归属，不按同名认人。
- PATCH_EQUIVALENT 不冒充 EXPLICIT_CHERRY_PICK，也不单独证明采用来源；部分采用不变成完整覆盖。
- 没匹配到不证明未被重写采用；历史计数与当前功能有效性分开。
- 本地 Git 分支引用数不当作 GitHub 正式 PR 数；主分支对象和历史范围可核对，缺历史不报完整累计值。

**证据：**预先构造的 Git 历史和独立期望值、源/上游映射、去重与不完整性断言。

### A09 — 历史基线和每日变化

**怎么验：**首次回填、随后新增已知提交/合并、无变化同步、后来确认旧采用、跨时区午夜、跨多天扫描与主分支非快进。

**通过条件：**
- 首次导入是历史基线，不是今日全部新增；无变化再次同步新增为零。
- mergedAt、原提交时间、首次观察进入主分支时间分别保存并注明口径。
- 新确认旧采用标为“新确认的历史采用”，不伪装当天合入。
- 跨多天可报“自上次同步”，不能无依据分摊每天。
- 非快进重写要求重新核对，不直接制造负“今日贡献”。

**证据：**固定时钟和日报期望表、基线/增量标记、对象集合对照。

### A10 — 本地命令、确认和报告

**怎么验：**阻断业务网络后运行状态、维护、统计、单 PR、额度和报告命令；本地处置反馈，再修改相关证据；测试空/部分数据库及恶意 HTML 文本。

**通过条件：**
- 普通读取和重算报告零业务网络请求、不隐式 fetch；init 与默认 doctor 同样离线。
- 终端、JSON 和报告数字一致，含范围、时间、证据和缺口；NO_ACTION 可默认折叠。
- 本地确认可跨重启保存，相关证据改变可重新打开复核，不写 GitHub。
- 成功、暂停、部分完成和失败可由退出结果和结构化字段区分。
- 外部文本不执行脚本、不加载跟踪资源、不把 token 放进链接。

**证据：**网络阻断断言、输出对照、本地处置恢复与文本转义测试。

### A11 — 实际目标只读验收

这是在线验收，不能用模拟测试替代，也不采用过去聊天的 PR/提交数量为答案。

必须执行：
1. 在实际本地环境用启动提示词参数配置；先小批只读试点，通过后完成当前 Open 和统计所需历史 PR 索引。
2. 完成全部普通 Open PR 的首次必要采集，每项有判定或具体不可得证据；不能只读标题就称全审查。手动排除项仍计统计。
3. 对至少 20 个真实普通 PR 逐项对照当前来源，覆盖实际存在的不同情况；若目标确实少于 20 个则全部检查。不在 GitHub 制造评论/修改来凑类型。
4. 固定主分支对象，完成身份与历史范围已核实的贡献基线，抽核正式合并、署名及可获得的间接采用证据。
5. 至少两次真实同步，验证稳定性、无重复和已发生变化。无真实变化时说明，变化场景由固定测试验证。

**通过条件：**
- 清单完整、样本无未解释差异；样本符合不等于全量语义准确率 100%。
- 限流暂停须按规则续跑；不能改成成功。个别身份权限/语义限制可接受，但必须具体披露。
- 整体连不上 GitHub、无法完成清单、缺完整主分支历史或实际安装失败，标 BLOCKED，不宣布最终完成。
- 对照来自逐条来源核验，不让同一个分类器生成自己的期望结果；开发智能体核查必须注明身份，不假称用户或独立第三方已验收。
- 真实数据仅本地保存；只有用户实际作出的确认才能登记为 user-confirmed。

**证据：**本地覆盖表、观测时间、样本对照、主分支对象、身份依据、两次同步差异和简单请求计数。不可公开个人原始数据。

### A12 — 公开安全、工程和发布

**怎么验：**检查已跟踪/暂存文件、全部待公开历史、最终归档；运行 Gitleaks 和路径检查；从干净提交安装；核对仓库、CI、标签、Release 和附件。

**通过条件：**
- 不含真实 token、SSH 私钥、实际配置、数据库、日志、个人报告或聊天/启动记录，输出也不泄露秘密。
- `.env.example` 仅空值/占位，`.gitignore` 在首次提交前建立；检查不限于当前 HEAD 文件。
- 公共仓库归属可真实，软件运行默认值不硬编码个人。
- 仓库确为本任务授权的 public 项目，有阶段代码提交；无覆盖无关仓库或强推贡献分支。
- CI 不依赖个人访问令牌（Personal Access Token，PAT），不扫描个人目标；模拟测试意外联网会失败。
- 待发布确切提交的类型检查、静态检查、测试、构建、公开检查通过，不能引用旧提交绿灯。
- 干净源码/运行归档含代码、真实锁文件、迁移、sample 和说明，解包后标准安装可用；不包含开发机 node_modules。
- v0.1.0 版本、标签、Release 对应同一验证提交；通用归档、校验值和实际发布链接已核对。
- 许可证、README、CONTRIBUTING、SECURITY、CHANGELOG 与实际功能一致。不 npm publish，不发布个人网页/云服务。

**证据：**仓库/提交/CI/Release 链接，干净安装日志、归档清单与校验、脱敏保密检查结果。

### A13 — 实现时选型、锁定与 sample 复现

**怎么验：**由开发者在 P0 选择一套常用稳定且受支持的参考环境，安装验证后用同一套环境、依赖锁和 sample 在干净目录重复安装。

**通过条件：**
- 设计阶段不预先填具体工具版本。交付时已实际选定并记录 Node/npm 参考版本，Node 优先长期支持版（Long-Term Support，LTS）。
- 一个 Node 版本选择文件、package 声明、锁文件、README 和 CI 相互一致。真实 `package-lock.json` 已验证；标准 `npm ci` 不重写锁文件。
- 不强制 Git/gh 或操作系统补丁号完全相同；明确兼容条件和实测版本即可。无需额外环境平台或专门冗余清单。
- 使用者按 README 和 sample 只改个人配置即可运行，不自行选库版本，不依赖未说明的全局 TypeScript/测试工具。
- SQLite、Git 与 CLI 在实际试点和干净 CI 环境通过；其他声明支持平台完成相应冒烟验证。未测平台如实说明，不假称全平台。
- 缺工具或确实不兼容有清楚提示；兼容但不同补丁号不必拒绝。不自动修改系统/全局设置或下载“最新版本”绕过错误。
- 无凭据离线流程可执行；gh 不是 env 认证或纯离线功能的隐藏必需项。环境摘要不导出全部环境变量/凭据。
- 固定测试数据、时钟、Git 对象与身份映射在已验证环境中业务结果一致；不要求跨系统二进制逐字节相同。

**证据：**实现后实际选用版本、锁文件标识、干净安装及 sample 运行记录、已验证平台说明。无需在交付前增加一份独立环境文档作为用户任务输入。

## 4. 验证入口与证据表

开发者提供并实际运行：

```text
npm run verify
npm run acceptance
```

`verify` 聚合静态检查、类型检查、测试、构建和公共文件检查；`acceptance` 执行固定合成业务、临时 Git 历史、恢复、离线输出及干净归档安装验收。环境检查可并入现有流程，不要求额外命令体系。

两条命令通过不替代真实试点、完整历史密钥扫描和同提交发布核验。依赖下载可联网，业务模拟测试必须隔离真实 GitHub。具体命令和工具参数在实现时核实，不能把本文命令列出就当已运行。

每个 A01—A13 可细分测试编号；至少记录：

| 字段 | 内容 |
|---|---|
| requirement_id | A01—A13 或子用例编号 |
| status | PASS / FAIL / BLOCKED / NOT_RUN |
| test_reference | 具体测试文件、场景或在线对照项 |
| command | 实际可复现命令 |
| expected | 运行前固定的正确期望，不由被测函数自己生成 |
| actual | 真实结果摘要，不含凭据 |
| code_commit | 验证的确切提交 |
| environment | 实际参考环境、平台与锁文件标识，简明即可 |
| evidence | 实际日志/CI/发布位置及核查人或智能体身份 |
| limitations | 缺口、影响和是否阻塞 |

公共仓库保存通用规范、合成测试和脱敏工程摘要。真实配置、20 项个人对照、原始响应、数据库、个人报告和含个人数据的执行日志只留本地。

测试或代码变更后重验受影响项，发布前在最终提交复核。不能移动验收门槛、放宽预期、删除失败测试来换绿灯。同一开发智能体编写与执行测试不等于独立评审。
