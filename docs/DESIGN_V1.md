# Contributor PR Ops — V1 设计与开发计划

文档版本：1.2 · 文档状态：执行规格；软件及验收尚未执行。

配套文档：[ACCEPTANCE_V1.md](ACCEPTANCE_V1.md)。本文件定义做什么、怎样实现、按什么顺序开发；配套文件定义怎样证明完成。

本套文档替代此前开发计划和固定环境草稿。**环境具体版本由开发者在实现时选择、验证并锁定，本文件不提前指定版本号。** 仓库所有者和真实试点参数从单独的本地启动提示词读取；该提示词及实际配置不得提交到公开仓库。

## 1. 项目目标与范围

开发一个独立、通用、本地优先（local-first）的个人开源贡献管理程序，项目名 `contributor-pr-ops`，命令名 `pr-ops`。

第一期只有两条业务线，共用采集结果和一个本地数据库：

1. **作者侧拉取请求（Pull Request，PR）维护**：找出指定作者在指定仓库中真正需要重新介入的开放 PR。不是维护者清理全仓库，也不是按年龄清理 PR。
2. **贡献统计**：统计正式合并的 PR、主分支署名提交、间接采用证据和每次同步的变化。

必须坚持：

- 软件无需智能体（agent）、大语言模型（Large Language Model，LLM）、聊天记忆或模型上下文协议（Model Context Protocol，MCP）服务即可运行。
- 确定性代码负责采集、状态、计数和规则；自然语言含义不能可靠确认时留给本地人工复核，不用关键词冒充理解。
- 运行时对被扫描仓库只读。开发期间创建、提交和发布本项目，是另一套授权。
- PR 年龄、落后主分支、长时间无人回复本身都不产生待办。
- 错误、不完整数据、缺权限和未知不能变成零、无冲突、无需处理或未采用。
- 第一期只支持 GitHub.com，单次配置一个目标仓库；作者、仓库、主分支、认证身份、时区均可配置。

**不做：**自动评论、关闭、重新打开、合并、解决审阅线程、变基（rebase）、推送或强推目标贡献分支；云端个人扫描；自动发布个人报告；大型前端；分布式限流；自动发布 npm。无需 Docker、Redis、Postgres 或智能体框架。

## 2. 直接复用与额外开发

| 部分 | 直接复用 | 我们实现 |
|---|---|---|
| GitHub 访问 | Octokit 及分页能力 | 统一只读客户端、指定作者采集、错误与覆盖度处理 |
| 节流 | `@octokit/plugin-throttling` | 配置比例、单请求队列、少量窗口状态 |
| 本地存储 | SQLite，优先兼容的 `better-sqlite3` | 表结构、迁移、快照、确认记录、统计账本 |
| Git 分析 | 原生 Git 命令行接口（Command-Line Interface，CLI） | 身份映射、提交匹配、去重、采用程度与时间归因 |
| 认证 | 本机 `gh` 或显式环境变量 | 认证身份选择，凭据隔离与输出脱敏 |
| CLI 与配置 | Commander、Zod、YAML 解析器 | 业务命令、sample 初始化、帮助及错误提示 |
| 测试与保密检查 | Vitest、Gitleaks | 业务场景、固定预期、公开路径与发布内容检查 |
| 业务与展示 | 不搬入完整第三方平台 | 作者维护规则、关联跟踪、贡献统计、终端及离线报告 |

Magpie、pr-inbox、OpenTelemetry Dashboard、gh-aw、GitHub MCP Server 和第三方贡献报表项目只可参考，不是运行依赖，不为复用而强行改造。复制代码时保留所需许可与归属；不要宣称他人代码是原创。

采用 TypeScript、一个 npm 项目、一个本地进程。目录和内部接口由开发者按最小可维护实现安排，不为目录示意创建空模块。

## 3. 环境：实现时选定，交付时可复现

**不采用旧稿预设的任何 Node、npm、Git、gh 或操作系统版本。**

P0 由开发者核查官方支持状态和实际依赖兼容性，选择一套常用、稳定、仍受支持的环境。Node 优先长期支持版（Long-Term Support，LTS），不追求刚发布的最新版本，不选预览版。

只要求以下交付：

1. 选定并记录一套参考 Node/npm 版本；用 `package.json` 和 `.nvmrc` 或 `.node-version` 中的一种记录。持续集成（Continuous Integration，CI）使用同一参考版本，不重复维护多套环境清单。
2. 真实生成并提交 `package-lock.json`；标准源码安装使用 `npm ci`。依赖在实现时验证后锁定，不能伪造锁文件，也不能让使用者自行搭配库版本。
3. Git、gh 等外部工具写清所需兼容条件和实测版本即可。无需强制每个人拥有相同补丁号；gh 只在 gh 认证或开发发布路径需要。
4. README 给出一条标准安装路线和一套 sample。使用者按说明安装，只改自己的账号、仓库及认证配置即可运行，不需要改源码或全局工具配置。
5. 干净目录完成安装、SQLite、Git 和命令行验证。不支持的环境给出明确说明；版本仅与参考补丁号不同但兼容时，不必一刀切拒绝。

**不新增环境管理平台，不要求 `toolchain.json`、两种 Node 版本文件或一组专门环境脚本。** 简单检查可以并入 `doctor`。环境升级时由维护者统一修改声明、锁文件、CI 和说明后重新验证，不在用户安装时静默升级。

开发时确定并记录平台支持范围，不预设操作系统发行版本。至少验证实际开发/试点平台和一个干净 CI 环境；声明支持的其他平台补做安装、Git/SQLite/CLI 冒烟验证，未验证的平台不宣称已支持。项目逻辑尽量原生跨平台，不要求使用者升级或重装操作系统。

## 4. 公共 sample 与个人配置隔离

公共样例为 `config/example.yaml`，初始化后生成被忽略的 `config/local.yaml`。支持 `--config <path>`。相对业务路径统一以实际配置文件所在目录解析，因此以下 sample 的数据目录为项目根目录下的 `.local/`。

```yaml
schema_version: 1

auth:
  method: gh
  account: your-github-user
  token_env: CONTRIBUTOR_PR_OPS_TOKEN

target:
  repository: example-org/example-repo
  author: example-contributor
  branch: main

rate_limit:
  quota_fraction: 0.40
  min_interval_ms: 2000
  max_retries: 2

maintenance:
  excluded_prs: []
  excluded_labels: []
  maintainer_overrides: []

git:
  checkout_path: null

attribution:
  verified_author_emails: []

storage:
  directory: ../.local

reporting:
  timezone: UTC
```

这是配置设计样例。开发者可以优化字段，但须同步实现、文档与测试，不降低功能。

- 认证账号与被统计作者独立，不写死 `author:@me`。公开默认值不绑定真实作者、项目、维护者名单或本机路径。
- `init` 不联网，不覆盖已有配置；配置缺失/非法时报错，不回退到开发者自己的目标。
- `maintainer_overrides` 是用户核实后的本地角色补充，不自动赋予 GitHub 权限。
- `.env.example` 只放说明与空的 `CONTRIBUTOR_PR_OPS_TOKEN=`。默认复用 gh 认证，不复制 token；环境变量模式才读取明确指定的本地环境文件，不遍历其他项目查找凭据。
- 凭据不得进入源码、配置正文、数据库、命令行参数、日志、错误对象和报告。不打印 `gh auth token` 输出，不读取或复制 SSH 私钥。
- 默认数据库、缓存、报告和真实验收明细统一保存在 `.local/`。自定义工作树内数据目录也必须被公开检查保护。

首次提交前建立 `.gitignore`，至少覆盖真实配置、`.env`（保留 `.env.example`）、`.local/`、数据库及辅助文件、密钥文件、日志、报告、依赖和构建产物、`LOCAL_ONLY_*`。示例、源码、迁移、锁文件和通用测试仍应被跟踪。

公共仓库所有者、项目 URL、正常版权和公开提交归属可以保留；保护个人运行配置不等于隐藏公开仓库身份。测试只使用合成账号、邮箱和数据，不提交真实 PR 抓取或本地启动提示词。

## 5. 总体结构与共享数据

```text
显式 sync / 在线诊断
  → 统一 GitHub 客户端与简单节流
  → 作者 PR、反馈、时间线、关联对象采集
  → SQLite：成功快照、变化、业务断点、局部确认
      ├─ 作者维护纯函数 → 待办、理由、证据、缺口
      └─ 贡献账本 + 本地 Git → 累计、增量、采用依据
  → 本地 CLI / JSON / Markdown 或静态 HTML 报告
```

贡献模块不能再独立全量读取一遍 PR；本地 Git 主分支获取一次，多模块共用。原生 Git 网络操作受同步顺序和频次约束，但不能假称它属于 GitHub API 的请求桶。

SQLite 按需要保存 PR 与快照、反馈、关系、角色依据、扫描记录/断点、简单额度状态、源/上游提交映射、采用证据和每日汇总。不强制一项一个表，不增加另一套存储服务。

## 6. 第一期功能设计

### F01 — 配置、身份和只读边界

实现第 4 节配置与认证选择。运行时 GitHub 接口只暴露读取；图查询语言（GraphQL）的查询允许使用 POST，但禁止 mutation，不能简单禁止所有 POST 来冒充只读控制。

本地 Git 默认在项目管理的独立克隆中分析。外部 `checkout_path` 只作已有数据来源，不修改用户工作树；需要更新时使用受控独立克隆。不得执行目标仓库的代码、测试、钩子、外部 diff/textconv，也不修改用户全局 Git 设置。

### F02 — 简单统一节流

所有应用程序接口（Application Programming Interface，API）请求与重试经过一个入口。

- 默认 `quota_fraction=0.40`，允许配置 0.30、0.50；合法范围为大于 0、不大于 1。
- 从官方文档及实际响应确定请求桶上限、剩余量、窗口和重置时间，不硬编码“普通账号总是某个固定额度”。本项目上限为对应官方额度乘比例，同时尊重服务端实际剩余量。
- 并发固定为 1，默认最小间隔 2 秒；低额度桶相应放慢，不先瞬间打满再等待。
- 普通请求与搜索按各自单位计量，GraphQL 按点数预留和校正。使用小型、可控查询，不把几百项及全部历史塞成一个超大查询。
- 直接复用节流插件的服务端等待处理。遵守 `Retry-After`/reset，最多两次重试；持续限流停止本轮，不换下一个 PR 继续打请求。普通权限错误不能无限重试。
- 只保存账号标识、桶、当前窗口用量/额度、重置与下次允许时间；不保存 token。重启不会重新获得同窗口预算。
- 一个简单本地锁阻止本项目两个 sync 并行；不做跨设备协调。

不开发每日预算平台、复杂熔断器、逐请求审计数据库、分布式限流和独立限流仪表盘。`rate` 显示少量当前状态即可。40% 是本项目默认余量，不是免限流保证；其他软件的流量不受本项目控制。实现时核对官方限流文档及插件实际行为，避免多层重试相乘。

### F03 — 作者 PR 索引与完整性

获取配置目标的当前 Open PR，包含草稿；同时为贡献统计取得历史正式合并和已关闭未合并的作者 PR。

顶层及评论、审阅、线程等嵌套数据均正确分页；超出搜索可返回范围时用支持的连接或分片查询，去重并记录完成情况。`first:100` 或搜索前 1000 条不能当全部。

每次记录已发现/已索引/已检查数量、缺口和观测时间。扫描期间实时变化可导致计数差异，要解释与核对，不保证瞬时强一致。读取失败时不将未返回的项目当成关闭。

### F04 — 快照、变化与恢复

保存稳定 PR 标识、head/base、状态、时间、草稿、可合并性、标签、反馈标识与内容版本、关联对象状态。`last_attempted_at` 与 `last_successful_at` 分开。

识别：新增/编辑评论、新审阅、新线程、head 变化、真实冲突变化、关联 Issue 变化、新交叉引用、外部代码变更和 PR 状态变化。

相同数据重复同步不重复生成待办或统计。中断保留进度，失败不覆盖上次成功快照。只有此前完整检查过且证据仍适用的结果才可复用；首次没读全不能直接 NO_ACTION。

PR 的 `updatedAt` 不是唯一失效依据：主分支、检查结果、既有关联来源可能独立变化。变化优先补采，安静项目低频轮转复核；缓存不是永远不再验证。

### F05 — 角色、逐项反馈和本地处置

角色为 SELF、MAINTAINER、THIRD_PARTY、BOT、UNKNOWN。关联标记、权限和本地核实表是证据；组织成员/协作者标签不自动代表最终决策权。同一账号依据复用，不每个 PR 重查。

每条反馈单独保存作者、类型、线程、创建/编辑时间、内容版本、原文链接、解决状态、相关回复和代码证据。

- 作者最后说过一句话，不等于所有意见处理完成；新提交也不等于对应修复。
- 旧 head 的审阅和已实质回应但仍未解决的线程，不机械反复提醒修改。
- 批准、感谢、维护者之间的协商不自动变成作者任务；非阻塞小意见仍可查看，不全部视为阻塞。
- 自然语言不能可靠确定时给出具体待核查项，不能依靠“fixed”“please close”等词确认完成或关闭。
- 提交作者/提交者不必然是推送操作者；仅发现外部提交但身份依据不足时如实标注。

`acknowledge` 只写本地，针对具体反馈/调查项记录已读、待处理、等待审阅、已确认等。确认绑定证据版本及必要 head；相关内容变化时重新进入复核。它不调用 GitHub resolve。

### F06 — 上游关系与采用线索

读取时间线（Timeline）中的交叉引用，保存来源 Issue/PR、动作账号、时间、关系及最后状态。必要时读取来源讨论；已经关联的对象之后关闭/合并，也应被发现，即使没有新引用事件。

Issue 关闭、相同文件、相似标题、duplicate/salvage 标签只是调查线索。明确上游决定也须核验对象、身份、语境与当前适用性。无关联 Issue 的 PR 不因此判无效。

无法由代码验证的完整功能覆盖或评论语义，通过带证据的本地人工确认进入决策；不要求系统自动解决所有语义问题。

### F07 — 作者维护决策

纯函数消费已采集事实与本地确认，不自行联网。输出主状态、并列线索、理由、来源、证据版本/观测时间和缺口，不能让一种状态遮掉其他待办。

| 状态 | 含义和边界 |
|---|---|
| `NO_ACTION` | 证据足够完整、新鲜，没有已知需要作者介入的事项；默认折叠 |
| `CONFLICT` | GitHub 明确确认真实冲突，未知不算没有冲突 |
| `MAINTAINER_ACTION` | 当前有效的维护者要求仍待作者响应；语义待核查须明确标注，不能声称已确认缺陷 |
| `THIRD_PARTY_FEEDBACK` | 第三方新反馈，进入定期查看队列，不自动当成维护者命令 |
| `WAIT_REVIEWER` | 具体反馈已有相关回应/经确认的修复，等待对方 |
| `MAINTAINER_EDITED` | 有维护者参与修改的依据，默认等待、不覆盖；并列保留新要求/冲突 |
| `UPSTREAM_CHANGED` | 原 Issue、引用或替代来源变化，需要调查 |
| `CLOSE_CANDIDATE` | 核实的明确上游决定或完整覆盖证据；仅建议，不关闭 |
| `INSUFFICIENT_EVIDENCE` | 数据、身份、语义或覆盖不足，必须说明缺什么 |

状态优先顺序写入代码与测试，全部线索仍可查询。已核查无待办、沿用旧结果、未检查必须区分。

保存并展示持续集成事实；实际测试失败、非必需检查、等待权限、旧 head 结果、基础设施失败和“无部署”不能混为一谈。当前有效且确需作者处理的失败不能被 NO_ACTION 隐藏，但不新增自动重跑和自动修复功能。

手动排除的 PR/标签退出普通维护队列，仍进入贡献统计。默认排除表为空，重点项由本地配置决定。

### F08 — 贡献统计与采用归因

必须分开三个维度：PR 的生命周期、代码被采用的程度、采用证据类型。

| 统计项 | 定义 |
|---|---|
| Open / Draft | 当前作者开放 PR 总数，草稿是其中子集 |
| 正式合并 PR | 作者 PR 有正式合并记录且目标为配置主分支，含普通/压缩/变基合并 |
| 关闭未合并 PR | 已关闭但没有正式合并记录；不等于没有任何代码被采用 |
| 主要作者与共同署名提交 | 当前主分支可达历史，按核实身份归属，分别计数并给出去重并集 |
| 非直接采用 | 源/上游提交映射、精确对象、等价补丁、明确拣选来源、部分采用与未知 |
| 每日/区间变化 | 正式新合并、首次观察进入主分支、新确认的历史采用分别显示 |

使用原生 Git 的历史、祖先关系、`git cherry`、`git patch-id --stable` 等能力，不自己重写 Git。以下证据标签可并存，不能相加冒充总贡献：

`DIRECT_PR_MERGE`、`EXACT_COMMIT_LANDED`、`PATCH_EQUIVALENT`、`EXPLICIT_CHERRY_PICK`、`PARTIAL_LANDED`、`UNKNOWN`。

关键规则：

- Git 姓名/邮箱与 GitHub 登录名分别处理，使用本地已核实邮箱映射或可靠 GitHub 归属依据；不凭重名计贡献。
- 上游提交按对象标识去重，PR 数不与提交数相减或相加推算 cherry-pick 数量。
- 等价补丁不是执行过 cherry-pick 的证明，更不能单凭内容相同确定来源作者；明确拣选须有对象对应的可核验来源。
- 匹配部分提交只记部分证据；全部单提交匹配也不能机械证明完整功能覆盖，须考虑后续修正、撤回及聚合差异。
- 没发现精确/等价证据不代表从未重写采用。默认“无已知采用证据/UNKNOWN”；若使用 `NOT_LANDED`，必须限定具体已验证范围。
- 历史可达但后来回退的提交可计历史归属，不自动成为当前 PR 可关闭依据。完整当前语义覆盖允许人工核查。
- 固定所分析的主分支对象，记录是否浅历史/缺对象；不完整时不给“已验证全历史总数”。本地 branch 引用数不冒充正式 PR 数。
- 首次回填是历史基线，不是今天全部新增；保存 mergedAt、原提交时间、首次观察时间及依据。跨多天同步显示“自上次同步”，不无证据分摊每天。
- 正常推进比较上次与本次主分支可达集合；非快进重写提示重新核对，不产生误导的负“今日贡献”。

### F09 — 本地 CLI 和报告

至少实现下列能力；参数可优化，文档、测试、实际接口须一致。

```text
pr-ops init
pr-ops doctor [--online]
pr-ops sync [--resume] [--limit N]
pr-ops status
pr-ops maintenance
pr-ops contributions
pr-ops pr <number>
pr-ops acknowledge <number> ...
pr-ops rate
pr-ops report
```

除明确 sync/回填/在线诊断外，命令从本地读取，不隐式联网或 fetch。提供终端、机器可读 JSON、Markdown 或静态 HTML 报告；不要求常驻 Web 服务。

报告含维护事项、贡献累计/增量、覆盖度、新鲜度、可点击证据和缺口。成功、暂停、部分完成和失败由退出结果及结构化字段区分。HTML 转义外部文本，不执行源评论脚本或加载跟踪资源；报告只留本地。

### F10 — 独立运行与业务续跑

默认手动一次性运行，不自动安装定时任务或个人 GitHub Actions 扫描。后续可以由用户自己的系统调度器调用命令，不开发常驻调度平台。

业务进度、反馈处置和统计账本在 SQLite 保存；关闭智能体或换开发会话不影响程序运行。后续开发者能按 CONTRIBUTING 添加规则及测试，无需修改个人硬编码。

## 7. 公开仓库与版本发布

必备内容：实际源码、测试、迁移、锁文件、环境版本声明、公共 sample、`.env.example`、`.gitignore`、README、LICENSE、CONTRIBUTING、SECURITY、CHANGELOG、通用 `AGENTS.md`、CI，以及本文件和 `ACCEPTANCE_V1.md`。环境、配置、限制与发布说明可以放 README 或简洁 docs，不要求大量重复文档。

- 默认许可证建议 MIT；执行时核实第三方许可，保留必要归属。README、提交、PR 说明和发布说明默认英文，可提供中文文档。
- `package.json` 设置 `private: true` 防误发 npm；GitHub 仓库仍为 public。
- 先安全检查，再首次推送。按阶段形成小提交/短期分支，不每改一个文件就推送，不用一次未验证的大提交代替阶段交付。
- 使用已核实的公开提交身份或 GitHub noreply 邮箱，不改全局 Git 身份，不默默公开私人邮箱。
- Gitleaks 配合小型公共文件检查，覆盖暂存/跟踪文件、待公开历史、最终归档。不能认为加 `.gitignore` 就能保护已跟踪的内容。
- 发现秘密或个人数据就停止公开操作，报告路径而不打印秘密。已经公开的秘密需提示撤销/轮换；不擅自改凭据或重写公共历史。
- CI 只验证本项目，用合成业务数据，不需要个人访问令牌（Personal Access Token，PAT），不上传个人报告。测试意外访问真实 GitHub 应失败。
- 工作流最小权限；第三方 Actions 核验来源并固定到完整提交。不用特权工作流执行不可信 PR 代码，不把个人 token 放进 Actions secrets。
- 本项目 main 有可用 CI 后启用必要检查和适当保护；避免唯一作者无法满足的自我审批条件。无权限设置的保护如实报告，不绕过验证。

发布门槛：

1. A01—A13 全部按交付标准通过；真实试点证据留本地，通用工程摘要可公开。
2. 从干净的待发布提交使用已选环境、锁文件安装并验证。
3. 标准交付为含源码、锁文件、迁移和 sample 的干净归档，解包后按 README 验证；不直接压缩当前本地目录，不携带 `node_modules` 或个人数据。
4. 如另交 `.tgz`，也做内容/安装检查；它不能替代标准源码归档的锁文件复现验收。不要求自行开发多平台二进制打包平台。
5. 对通过 CI 的同一个提交创建 `v0.1.0` 标签及 GitHub Release，核对版本、标签、提交和附件，提供归档校验值及已知限制。
6. 已发布标签不移动；修复发新版本。不发布 npm、个人网页、云服务或个人扫描定时任务。

仓库创建和写入对象只从启动提示词读取。同名仓库只能在确认属于本任务时续做，否则停止该远程写入，不覆盖、不强推、不自动创建一串备用仓库。

测试先离线，再经统一客户端做真实只读试点；不用真实 GitHub 压测，不用过去聊天中的数量当当前期望。暂停后按节流规则续跑。外部受阻时继续完成可做的本地工作，但不得伪造在线或发布完成。
